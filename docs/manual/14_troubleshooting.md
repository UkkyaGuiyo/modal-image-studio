# 14 エラー切り分け・復旧

切り分けの本体は [docs/troubleshooting.md](../troubleshooting.md)（「こんな時どうしたら？」形式）です。
この章では進め方だけを定めます。

## 手順：エラーに当たったときの型

- 目的：場当たり的な試行錯誤を避け、根拠のある順序で直す
- 前提条件：エラーまたは意図と違う結果が出た
- 実行主体：Muse
- コマンド：まず症状を [トラブルシューティング](../troubleshooting.md) で検索する
- 成功条件：該当項目の「原因の確認→直し方」で解消する
- 失敗時の切り分け：該当項目が無い場合は、開発ログ（[docs/development-log/](../development-log/)）の症状が近い記録を読む。それでも分からなければ「原因不明」と人間に報告し、勝手な連続試行で費用を溶かさない
- 次のステップ：解消したら、使った項目の試験IDを添えて人間に報告する

## 切り分けの原則（開発時の実測から）

1. **同時実行を疑う**：Modal 系のエラーはまず「modal run を並列に出していないか」
2. **モデルの限界と、こちらのミスを分ける**：日本語文字・移動・視点変更はモデルの限界（実測確定）。文字の欠けはこちらの合成ミスのことがある
3. **seed を変えるのは最後の手段ではなく常套手段**：枠アーティファクト等の稀な欠陥は seed 変更で消える
4. **費用のかかる再試行は1回ずつ**：結果を見てから次を決める
