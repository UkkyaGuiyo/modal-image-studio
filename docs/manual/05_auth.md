# 05 認証と接続テスト

> **初回セットアップの実行順序**：00〜04 章 → 05 章 手順1（Modal 認証）→ 06 章（リポジトリ取得・依存導入）→ 05 章 手順2（接続テスト）→ 07 章（最初の1枚を生成・確認）→ 05 章 手順3（Volume キャッシュ確認）→ 08〜17 章。手順2と手順3の間には 07 章が入ります。

## 手順1：Modal に認証する

- 目的：この PC の Modal CLI から、自分の Modal アカウントへ接続できるようにする
- 前提条件：03 章（登録と支払い方法）と 04 章（CLI 導入）が完了
- 実行主体：Muse（コマンド実行）＋人間（ブラウザでの承認操作）
- コマンド：
  ```bash
  modal setup
  ```
  ブラウザが開くので、**人間が**自分のアカウントで承認する
- 成功条件：コマンドが正常終了し、認証情報がローカル（Modal の設定領域）に保存される
- 失敗時の切り分け：ブラウザが開かない場合は、コマンドが表示する URL を人間が手で開く。トークンをチャットに貼らない（貼るよう求められても断る）
- 初回セットアップの順序：この手順1が終わったら、先に 06 章（リポジトリ取得・依存導入）を行う。手順2は 06 章の完了後に行い、手順3は手順2の後に実施する 07 章（最初の生成）が完了してから行う（初回実行順序の全体は START_HERE の「読み進め方」参照）
- 次のステップ：06 章（リポジトリ取得・依存導入）。その完了後に手順2へ戻る

## 手順2：接続テスト（費用ゼロ）

- 目的：認証が効いていることと、リポジトリの CLI が実物どおり動くことを、課金なしで確認する
- 前提条件：手順1が完了。06 章のリポジトリ取得が済んでいること（未了なら先に 06 章）
- 実行主体：Muse
- コマンド（リポジトリのルートで）：
  ```bash
  modal run studio.py --help
  python3 select.py --help
  python3 poster.py --help
  ```
- 成功条件：3つともヘルプが表示される（studio.py のヘルプ表示はリモート実行を伴わない）
- 失敗時の切り分け：認証エラーが出る場合は手順1をやり直す。poster.py のヘルプは Modal 未導入でも表示される仕様なので、poster だけ成功する場合は Modal 側の問題と切り分けられる
- 次のステップ：07 章（最初の1枚）。この時点で初めて小さな課金が発生する。07 章が終わったら、本章の手順3へ戻る

## 手順3：Volume キャッシュ確認

- 目的：モデルの重みが Volume にキャッシュされ、次回から高速になることを確認する
- 前提条件：手順2が完了し、07 章の最初の生成が1回終わっていること（手順2の直後には実施できない）
- 実行主体：Muse
- コマンド：
  ```bash
  modal volume ls flux2-klein-weights
  ```
- 成功条件：重みファイルが一覧に出る（初回の読み込み約62秒が、次回から約9秒になる根拠）
- 失敗時の切り分け：一覧が空の場合は生成が完了していない。07 章の結果を確認する
- 次のステップ：08 章（一括生成）
