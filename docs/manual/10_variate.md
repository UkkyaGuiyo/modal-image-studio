# 10 バリエーション再展開

選んだ画像を参照して、絵を展開します。考え方は3モードです（モードはプロンプトの書き方で実現します）。

| モード | 向いていること | 実測評価（P3-001） |
|---|---|---|
| Preserve（保持） | 被写体と構図を保ち、指定した要素だけ変える（季節・時刻・天候・背景の一部） | 12/12 完全通過（平均6.0/6.0） |
| Restyle（作風変更） | 構図そのままに画風・色調を変える | 12/12（平均6.0/6.0） |
| Explore（探索） | 場面そのものを変えて発想を広げる | 平均4.0。被写体の移動・視点変更は苦手（下記） |

## 手順1：選択画像から展開する

- 目的：09 章で記録した選択を親にして、バリエーションを作る
- 前提条件：selection.json がある
- 実行主体：Muse
- コマンド：
  ```bash
  modal run studio.py --mode variate --from-selection runs/<日時>_<名前> \
    --prompt "Change the scene to a winter night with aurora borealis, keep the cabin and composition" \
    --count 4 --run-name winter
  ```
- 成功条件：新しい run ができ、manifest の各画像の `parent` に「<元run>/img_00X.png」が記録される（系譜が追える。P4-001 で実走確認済み）
- 失敗時の切り分け：selection.json が無い run を指定するとエラーになる。09 章に戻る
- 次のステップ：新しい run を 09 章の手順で提示し、必要なら繰り返す

## 手順2：任意の画像から展開する

- 目的：選択を経ていない画像（手持ちの PNG 等）を親にする
- 前提条件：親にしたい PNG がある
- 実行主体：Muse
- コマンド：
  ```bash
  modal run studio.py --mode variate --ref path/to/image.png \
    --prompt "Make the sky a starry night, keep everything else" --count 4 --run-name night
  ```
- 成功条件：新しい run ができ、parent に元ファイル名が記録される
- 失敗時の切り分け：—
- 次のステップ：09 章の提示へ

## 手順3：苦手な指示の出し方を変える（実測に基づく）

- 目的：モデルの弱点に当たる指示を、通る形に言い換える
- 前提条件：展開結果が意図と違う
- 実行主体：Muse
- コマンド：なし（下表でプロンプトを直して再実行）
- 成功条件：言い換え後に意図どおりの変化が得られる
- 失敗時の切り分け：下表でも通らない場合は、その変更は現行モデルの限界として人間に報告する
- 次のステップ：09 章の提示へ

| やりたいこと | そのまま言うと | 言い換え |
|---|---|---|
| 被写体を左へ動かす | 左に新しい被写体が**増えて**元も残る（BENCH-001 C4） | 2段階で行う：①「〜を取り除いて」で消す → ②消えた画像を親に「左側に〜を描いて」 |
| 視点を変える（対岸から） | 元の構図のまま返る（P3-001） | 視点変更は諦め、場面・季節・時刻の変更で代替する |
| 絵の中の看板に文字を書く | 指定位置に書かれず、別の場所に崩れて出る（BENCH-001 C5） | 文字は生成で入れない。12 章の合成で入れる |
| 作風を保ったまま場面変更 | 作風が指示なく写真風などに漂移することがある（P3-001） | 作風語（例：flat illustration）をプロンプトに明記する。`--style` 併用も可 |
| 数を増やす・減らす | —（これは得意。猫3匹は正確だった。BENCH-001 C3） | そのまま「three cats」のように数を明示する |
| 矛盾する要求（夕日は赤く、空は青く） | —（空間で分けて解決することがある。同 C2） | 「地平線だけ」「上空は」のように場所を分けて書くと通りやすい |
