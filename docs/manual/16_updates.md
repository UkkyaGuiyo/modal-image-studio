## 互換性で気をつけること

- **diffusers は GitHub 本流から導入している**（モデルカードの指示に従った開発時の構成）。将来 pip の安定版に切り替える場合は、生成とブレンドの両方でスモークテスト（07 章と 12 章手順1〜3）をやり直すこと
- モデルIDを変えると、初回は重みの再ダウンロード（約62秒級）が走る。Volume はモデルごとに使い分けるのが安全
- Modal CLI のバージョンが変わると `--help` の表示が変わることがある。手順書のコマンドと食い違ったら、実物の `--help` を正とする

## Modal の料金・クレジット条件の定期確認

この道具は Modal の無料クレジット（Starter プラン、月 $30）を前提にしています。クレジット額や料金条件は、提供側の都合で変更されることがあります。変更に気づかないまま使い続けないよう、定期確認を運用ルールとして定めます。

> 実例：2026年10月1日から、ネットワーク egress の課金が開始されました。Starter は月1TiBまで無料、超過分は $0.04/GiB です。この無料枠は Workspace 全体に適用されるもので、Environment ごとに別枠が与えられるものではありません。これは月 $30 の Compute クレジットとは別の料金条件で、クレジットが残っていても転送料金が発生し得ます。本丸の $30 クレジット自体は維持されていましたが、周辺条件は実際に変わります。

## 手順：月に1回の条件確認

- 目的：無料クレジットや料金条件の変更を見逃さず、前提が崩れたら先に人間に知らせる
- 前提条件：月に1回実施する。前回の実行から1か月以上空いている場合は、作業の前に必ず実施する。前回の確認記録がある場合は、その内容と突き合わせて差分を見る（記録が無ければ、今回を初回確認として基準値にする）
- 実行主体：Muse
- コマンド／確認先：
  - Modal の公式料金ページ（https://modal.com/pricing）で、Starter プランのクレジット額と主な従量項目を確認する
  - `modal billing rates` で現在の料金単価（GPU・CPU・Memory 等）を取得し、料金ページの表記と突き合わせる
  - egress の料金条件は公式ガイド（https://modal.com/docs/guide/network-egress-billing）で確認する。当月の egress 使用量は Dashboard の Usage & Billing で確認する（無料枠と集計単位は Workspace 全体であり、Environment ごとに別枠ではない点に注意。Usage & Billing では Environment 別に絞り込んで表示できるが、それは表示上の絞り込みであり、無料枠が Environment ごとに分かれる意味ではない）
  - `modal billing summary` で当月の消費状況と見比べる（13 章手順2）
- 確認項目（すべて確認する）：
  - Starter の月間 Compute クレジット額
  - クレジットの適用範囲（どの料金項目に充当されるか）
  - GPU・CPU・Memory の単価
  - Volume の無料枠と超過料金
  - Network Egress の無料枠と超過料金
  - 新設の課金項目の有無
  - プラン構成・支払い条件の変更
- 成功条件：確認項目をすべて確認し、結果を下記の形式で記録した。クレジット額と主な料金条件が前回確認時から変わっていない、または変更点をすべて把握した
- 失敗時の切り分け：変更があった場合（クレジット額の変更、新しい課金項目の追加、プラン構成の変更）は、**有料の Modal 操作を実行する前に人間に報告する**。あわせて、この手順書の該当する数値（00 章・11 章・13 章）を実態に合わせて更新する。料金ページ・ガイドにアクセスできない等で確認できない項目がある場合は、その項目を「未確認」として人間に報告し、確認できたものとして扱わない
- 次のステップ：問題がなければ通常の作業へ。変更があった場合は、人間の判断を待ってから進める

### 確認結果の記録

確認のたびに、次を記録として残すこと：確認日／確認した公式URL（料金ページ・egress ガイド等）／主要条件（クレジット額・主な単価・無料枠）／前回からの変更点／判定（変更なし／変更あり／未確認）。

- 前回の記録が無ければ、初回確認として今回の内容をそのまま基準値にする
- **記録の置き場所は公開リポジトリの外**（利用者自身の永続的な記録場所）にすること。アカウント固有の請求額・利用履歴は公開 GitHub に入れない
- 保存先が指定されていない場合は、人間に保存先を確認すること。保存先が決まるまでは、確認記録の保存を完了したものとして扱わない
