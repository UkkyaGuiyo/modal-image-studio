# 15 開発の失敗と修正履歴

この道具の開発記録は [docs/development-log/](../development-log/) にあります。
完成した手順だけではなく、**試して失敗したこと・原因・直し方**を含んでいるのが特徴で、
トラブルシューティングの各項目は、ここの試験IDを根拠にしています。

## 索引（要点のみ。全⽂は development-log 側）

| ID | 内容 | 手順書への反映 |
|---|---|---|
| P1-001 | 最小実行。生成3.83秒/枚、読み込み初回62秒 | 07章・11章の実測値 |
| P2-001 | 一括生成＋manifest＋コンタクトシート | 08章の形式 |
| P3-001 | 品質ゲート36枚。Preserve/Restyle 満点、Explore の弱点を特定。同時起動のレート制限も記録 | 10章のモード評価、同時実行禁止ルール |
| P4-001 | 製品版CLIで選定の循環を実走 | 09〜10章の手順 |
| P5-001 | poster.py 製品化。ガードの誤検知と Modal 定義スコープの失敗も記録 | 12章のツール仕様 |

## 読み方

- 原因が分からなかった記録には「原因不明」と書いてあります。推測を確定原因として書かないのがこのログのルールです
- 自分の環境で新しい失敗に出会ったら、同じ形式（症状／原因の確認／直し方）で記録を足すと、次の切り分けが速くなります
