# 06 リポジトリ取得と依存導入

> 初回セットアップの実行順序は、00〜04 章 → 05 章 手順1（Modal 認証）→ 06 章（リポジトリ取得・依存導入）→ 05 章 手順2（接続テスト）→ 07 章（最初の1枚を生成・確認）→ 05 章 手順3（Volume キャッシュ確認）→ 08〜17 章 です。本章が終わったら 05 章 手順2へ戻ります。初回実行順序の全体は START_HERE の「読み進め方」も参照してください。

## 手順1：リポジトリを取得する

- 目的：このリポジトリのファイルを手元に置く
- 前提条件：04 章が完了
- 実行主体：Muse
- コマンド（Git の場合）：
  ```bash
  git clone <このリポジトリのURL>
  cd modal-image-studio
  ```
  ZIP の場合：配布された ZIP を展開し、そのフォルダへ移動する
- 成功条件：ルートに `studio.py` / `select.py` / `poster.py` / `START_HERE.md` がある
- 失敗時の切り分け：clone 先のフォルダ名が違う場合は、そのフォルダ名で読み替える（以降の手順はリポジトリのルートを作業ディレクトリとする）
- 次のステップ：手順2

## 手順2：依存を入れる

- 目的：ローカルツールの依存（Modal CLI と Pillow）をそろえる
- 前提条件：手順1が完了
- 実行主体：Muse
- コマンド：
  ```bash
  pip install -r requirements.txt
  ```
- 成功条件：エラーなく完了する
- 失敗時の切り分け：04 章で導入済みなら実質の再確認になる。バージョン競合が出た場合は仮想環境を分ける
- 次のステップ：手順3

## 手順3：フォルダ構成を理解する

- 目的：どこに何が生成され、何を Git に入れてはいけないかを把握する
- 前提条件：手順1が完了
- 実行主体：Muse（読むだけ）
- コマンド：なし
- 成功条件：下記の区別が説明できる
- 失敗時の切り分け：—
- 次のステップ：05 章 手順2（接続テスト）→ 07 章（最初の1枚）→ 05 章 手順3（Volume キャッシュ確認）

| 場所 | 中身 | Git に入れるか |
|---|---|---|
| `studio.py` / `select.py` / `poster.py` | 本体ツール | 入れる |
| `docs/` | 手順書・Howto・開発ログ | 入れる |
| `samples/` | 作例の説明文（SAMPLES.md のみ。画像ファイルは収録しない） | SAMPLES.md のみ入れる |
| `runs/` | 生成結果（画像・manifest・selection） | **入れない**（.gitignore 済み） |
| Modal Volume `flux2-klein-weights` | モデルの重みキャッシュ | クラウド側のみ |

次のステップ：[05 認証と接続テスト](05_auth.md) の手順2
