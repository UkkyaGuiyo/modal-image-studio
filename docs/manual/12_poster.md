# 12 ポスター制作と保存・書き出し

ポスターの文字は、生成モデルには描かせません（日本語は疑似漢字になることが実測で確定。TEXT-001）。
標準工程は次の4段です（TEXT-003 で確定）：

1. 背景の絵を用意する（studio.py で生成・選択）
2. HTML/CSS で文字を正確に合成する（poster.py render）
3. （任意）ブレンドパスで文字の周辺だけをAIで馴染ませる（poster.py blend）
4. 最後に元の文字レイヤーを重ね直し、字形をピクセル単位で保証する（blend に内蔵）

## 手順1：文字を合成する（費用ゼロ）

- 目的：背景画像に、正確な日本語タイトルなどを載せる
- 前提条件：背景に使う PNG（無くてもよい。その場合は単色グラデーションの背景になる）。Chromium と日本語フォント（02 章）
- 実行主体：Muse
- コマンド：
```bash
python3 poster.py render --bg runs/<日時>_<名前>/img_002.png \
--template orderly \
--title "星空の灯台" --subtitle "満月の夜、港を照らす" \
--band-left "2026年 夏 公開予定" --band-right "入場無料" \
--out poster_out
```
- 成功条件：`poster_out/` に composite.png（完成見た目）と textlayer.png（文字だけの透明レイヤー）ができる。全ての文字が指定どおり正確に表示されている
- 失敗時の切り分け：
- Chromium が見つからない → `--chrome <パス>` か環境変数 CHROME_BIN で指定する
- 文字が豆腐（□）になる → 日本語フォント（Noto CJK）が入っていない
- 次のステップ：手順2（必須の確認）

## 手順2：文字レイヤー単体を確認する

- 目的：合成ミス（文字の欠け・抜け）を、ブレンドで「正確に保存」してしまう前に発見する
- 前提条件：手順1が完了
- 実行主体：Muse
- コマンド：なし（`poster_out/textlayer.png` を単体で開き、タイトル・サブ・帯の全文字がそろっているか目視する）
- 成功条件：全文字が欠けなく存在する
- 失敗時の切り分け：欠けていたら合成側の問題。文言とテンプレートを見直して手順1からやり直す
- 次のステップ：手順3または手順4

> 根拠：デザイン再現ベンチマークで、こちらの合成コードのバグでタイトル1字が欠落し、ブレンドが欠落ごと正確に保持した実例がある（BENCH-002 の失敗記録）。ブレンドは入力を守る工程なので、入力の確認が先。

## 手順3：ブレンドで馴染ませる（任意）

- 目的：文字の周辺だけを再描画し、貼り付け感を消して絵と一体化させる
- 前提条件：手順2の確認が済んでいる
- 実行主体：Muse
- コマンド：
```bash
python3 poster.py blend --bg runs/<日時>_<名前>/img_002.png \
--template orderly \
--title "星空の灯台" --subtitle "満月の夜、港を照らす" \
--band-left "2026年 夏 公開予定" --band-right "入場無料" \
--out poster_out
```
- 成功条件：`poster_out/final.png` ができ、全文字列が composite.png と一字一句同じ。費用は poster_manifest.json に記録される（実測約 $0.006）
- 失敗時の切り分け：
- 「Blend prompt mentions text」で止まる → ブレンド用プロンプトに文字への言及が入っている。画風だけの抽象的な文に直す（実測ルール：文字に触れると再描画されて崩れる。TEXT-003）。poster.py はこの検査を自動で行う
- 装飾（星マーク等）が消えた → 装飾が文字に近すぎて一緒に再描画された。装飾を文字から離して配置する（BENCH-002）
- 次のステップ：手順4

ブレンドの標準値（変更不要）：保護＝文字＋6px、再描画＝周辺44pxの帯（halo）、6 steps、guidance 1.0。
応用：`--blend-mode full` にすると、文字を固定したまま**絵の側だけを全面リスタイル**できる（ビンテージ印刷調など。TEXT-003 の V3）。

> 印刷物らしくシャープな仕上がりが欲しい場合（募集ポスター等）は、ブレンドなしの composite.png のほうが向いている（実例：samples/29_poster_recruitment.png）。

## テンプレート3種

| テンプレート | 寸法 | 特徴 | 主なスロット |
|---|---|---|---|
| orderly | 1024×1024 | 整然。縦書き明朝タイトル＋字間広めのサブ＋下グラデーション帯 | --title / --subtitle / --band-left / --band-right |
| art-broken | 1024×1024 | 崩し。1字ごとに大きさ・角度・色を変えたタイトル、斜めの赤テープ、回転バッジ、透かし大文字 | --title / --subtitle（テープ） / --frag1 / --frag2 / --badge / --band-left / --watermark |
| recruit | 832×1248 | 実務系。上部に写真帯、太いタイトル、条件の円3つ、下線の告知行、フッター（団体名・連絡先・QR枠） | --tag / --ribbon / --title-main / --title-sub / --title-line2 / --circle1〜3 / --visit / --org-name / --org-info |

スロットは `--slots-json '{"TITLE":"..."}'` の形でも上書きできる。文言中の改行は円内テキスト等でそのまま改行として効く（--badge / --circle1 など）。

## 手順4：文字を躍らせる・奥行きを持たせる（応用テクニック）

生成で入れる文字は「行」として静止して描かれるため、躍動や奥行きは合成側の仕事です（BENCH-002 補足）。

- 目的：タイトルに動きや奥行きを与え、デザインの主役にする
- 前提条件：手順1〜2ができること
- 実行主体：Muse（poster.py が出力する poster.html を編集し、同じ Chromium で再描画する）
- コマンド：
```bash
# poster_out/poster.html を編集した後、同じ条件で撮り直す
<Chromiumのパス> --headless=new --no-sandbox --window-size=1024,1024 \
--screenshot=poster_out/composite.png file://$PWD/poster_out/poster.html
```
- 成功条件：文字が静止した行ではなく、大きさ・角度・深度を持つ要素として絵に組み込まれている
- 失敗時の切り分け：やりすぎると可読性が落ちる。タイトルとして読めることが最低条件
- 次のステップ：手順3（ブレンド）または保存

テクニックの実測内容：
- **躍る文字**：1字ごとに font-size・rotate・translateY を変え、ブロック全体も少し傾け、画面端ではみ出させる。art-broken テンプレートがこの考え方の出発点（実例：samples/27_poster_dancing_type.png）
- **パース文字**：奥行きのある構図で、文字を3つの深度に置く。消失点に小さく、路面には `transform: perspective(360px) rotateX(57deg)` で路面標示のように、手前には画面からはみ出す巨大文字（実例：samples/28_poster_road_perspective.png）
- **ルビ・混植**：HTML の `<ruby>` でふりがな、日英混植もそのまま書ける（TEXT-004 で実測。ブレンド後も正確）

## 手順5：保存と書き出し

- 目的：成果物を後から追える形で残す
- 前提条件：手順1（または3）が完了
- 実行主体：Muse
- コマンド：なし（poster_out/ 一式を保管する）
- 成功条件：poster_manifest.json に、使ったテンプレート・文言・設定・費用が記録されている。最終成果は composite.png（ブレンドなし）または final.png（ブレンドあり）
- 失敗時の切り分け：生成画像や poster_out は Git に入れない（06 章）。共有する場合はファイルそのものを渡す
- 次のステップ：13 章（費用確認・停止・削除）
