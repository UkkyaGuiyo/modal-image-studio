# 13 費用確認・停止・削除

## 手順1：直近の実行費用を確認する

- 目的：1回ごとの消費を把握する
- 前提条件：生成やブレンドを実行したことがある
- 実行主体：Muse
- コマンド：なし（対象 run の `manifest.json`、ポスターの `poster_manifest.json` を読む）
- 成功条件：gpu_seconds と est_cost_usd が読み取れる（studio.py の実行は標準出力にも同じ JSON が出る）
- 失敗時の切り分け：—
- 次のステップ：手順2

注意：`est_cost_usd` はGPU費用の推定であり、CPU・メモリ等を含む総請求額ではありません（総請求額は手順2の請求ベースで確認します）。手順書内の実測値（例：候補8枚 約 $0.011）はいずれもモデルキャッシュ後の条件で、初回実行は読み込み（約62秒）込みで約 $0.027〜0.029（目安 約$0.03）かかります。

## 手順2：請求ベースで確認する

- 目的：クレジットの消費と残りを公式の数字で確認する
- 前提条件：Modal に認証済み
- 実行主体：Muse（照会）＋人間（金額の判断）
- コマンド：
  ```bash
  modal billing summary
  ```
  詳しくはダッシュボード（Billing）でも確認できる
- 成功条件：当月の使用額とクレジット消費が分かる
- 失敗時の切り分け：コマンドの結果とダッシュボードが食い違う場合は、ダッシュボードを正とする
- 次のステップ：予算上限（03 章で人間が設定）に近づいていたら人間に報告する

## 手順3：実行中の処理を止める

- 目的：走っている生成やアプリを止める
- 前提条件：止めたい実行がある
- 実行主体：Muse
- コマンド：
  ```bash
  # ローカルで実行中なら Ctrl-C で止めるのが基本
  modal app list
  modal app stop <アプリ名>
  ```
- 成功条件：対象アプリが一覧から消える、または停止済みになる
- 失敗時の切り分け：`modal app stop` はアプリと実行中コンテナを恒久的に止める操作。対象のアプリ名（この道具は `image-studio`）を間違えないこと
- 次のステップ：手順4（後片付けが必要な場合）

## 手順4：ローカルの成果物を消す

- 目的：不要な生成結果を整理する
- 前提条件：消してよい run が決まっている（**人間に確認してから**）
- 実行主体：Muse
- コマンド：
  ```bash
  rm -rf runs/<日時>_<名前>
  ```
- 成功条件：対象フォルダが消える。manifest も一緒に消えるため、再現に必要な条件（プロンプト・seed）も失われる点に注意
- 失敗時の切り分け：残しておきたい絵がある場合は、画像だけを別の場所へコピーしてから消す
- 次のステップ：手順5（完全にやめる場合のみ）

## 手順5：重みのキャッシュを消す（完全停止用）

- 目的：Modal 側のモデルキャッシュを削除し、完全に初期状態へ戻す
- 前提条件：今後しばらく使わないことが決まっている
- 実行主体：Muse（**人間の承認後**）
- コマンド：
  ```bash
  modal volume delete flux2-klein-weights
  ```
- 成功条件：Volume が削除される。次回実行時は初回と同じ約62秒のダウンロードから始まる（11 章）
- 失敗時の切り分け：Volume 名を間違えると別データを消す危険がある。実行前に `modal volume ls flux2-klein-weights` で中身を確認する
- 次のステップ：アカウント自体の解約は人間がダッシュボードで行う（Muse の担当外）
